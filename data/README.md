# Dataset layout

## Your 3 datasets — exactly where each one goes

| Dataset | Unzip into | Import with | Role |
|---|---|---|---|
| INCLUDE (word signs, landmarks included) | `data/raw/include_raw/` | `python data/import_include.py` | Trains the CNN-LSTM sign classifier (263 word classes) |
| ISLTranslate (30k sentence pairs) | `data/raw/isl_translate_raw/` | `python data/import_isltranslate.py --mode direct` (then `--mode pseudo_gloss` after the sign model is trained) | Trains the Transformer NLP sentence-correction module |
| ISL-CSLTR (700 sentence videos, SASTRA) | `data/raw/isl_csltr_raw/` | `python data/import_isl_csltr.py` | Continuous-signing training data + a second source of sentence pairs |

**Before running any importer**, always inspect the actual unzipped layout
first — Kaggle/GitHub dataset internals vary between uploads and versions:
```
python data/inspect_dataset.py --path data/raw/include_raw
python data/inspect_dataset.py --path data/raw/isl_translate_raw
python data/inspect_dataset.py --path data/raw/isl_csltr_raw
```
Each `import_*.py` script has an `# IMPORTANT` docstring explaining exactly
which assumption to edit if your folder structure doesn't match.

### Why these three don't just merge automatically — read this once

- **INCLUDE** ships MediaPipe landmarks already extracted, per isolated
  word. It's the only one of the three with clean word-level gloss labels
  ("WATER", "HELLO", ...) — so it's what actually trains the sign
  recognizer.
- **ISLTranslate** gives you (signed video/pose) ↔ (English sentence) pairs
  for continuous signing — but **no word-by-word gloss annotation**. So it
  can't directly fill a `gloss_sequence,english_sentence` training file.
  `import_isltranslate.py --mode direct` gets the pose↔sentence pairs in;
  `--mode pseudo_gloss` (run **after** the sign model is trained on
  INCLUDE) segments each sentence's pose sequence into windows, runs your
  trained sign classifier over each window, and stitches the predicted
  glosses into a pseudo-gloss sequence paired with the real English
  sentence — that's what actually trains the transformer.
- **ISL-CSLTR** is raw sentence videos with sentence-level text
  annotation (not pre-extracted landmarks, not word-level gloss either) —
  `import_isl_csltr.py` runs MediaPipe on the videos itself, then feeds
  into the same pseudo-gloss step as ISLTranslate.

So the real training order is:
```
1. import_include.py            -> train_sign_recognition.py   (train the sign classifier first)
2. import_isltranslate.py --mode direct
3. import_isl_csltr.py
4. import_isltranslate.py --mode pseudo_gloss   (needs the trained sign model from step 1)
   (do the same pseudo-gloss pass for ISL-CSLTR's sentence_pairs csv)
5. train_transformer_nlp.py     -> trains on the combined pseudo-gloss/English pairs
```

## Generic layout (used by data/prepare_dataset.py for your own future recordings)

Since you said the dataset is already downloaded, place it here following

this structure (matches INCLUDE / ISLTranslate / FER2013 conventions
referenced in the project). Adjust paths in `src/training/config.py` if your
folder names differ — everything reads from there.

```
data/
├── raw/
│   ├── sign_videos/                # INCLUDE-style: one folder per class
│   │   ├── water/
│   │   │   ├── water_001.mp4
│   │   │   ├── water_002.mp4
│   │   │   └── ...
│   │   ├── hello/
│   │   └── ...
│   ├── isl_sentences/               # ISLTranslate-style parallel corpus
│   │   └── isl_gloss_english_pairs.csv   # columns: gloss_sequence, english_sentence
│   ├── fer2013/
│   │   └── fer2013.csv              # standard Kaggle FER2013 dump
│   └── regional/                    # self-collected dialect samples
│       ├── south/
│       │   └── water/water_sindx_001.mp4
│       ├── north/
│       │   └── water/water_nindx_001.mp4
│       └── maharashtra/
│           └── water/water_mindx_001.mp4
└── processed/                        # generated by prepare_dataset.py — do not edit by hand
    ├── landmarks/
    │   └── <class_name>/<video_id>.npy     # (T, 258) landmark sequences
    ├── labels.csv
    └── splits/
        ├── train.csv
        ├── val.csv
        └── test.csv
```

Landmark vector per frame is 258-dim:
`21 pts × 3 (x,y,z) × 2 hands = 126` + `468 pts × ... ` — see
`landmark_extraction/extract_landmarks.py` for the exact reduced feature
set used (we take a compact subset of face points, not all 468 raw, to keep
the sequence model tractable on-device).

Run:
```
python data/prepare_dataset.py --dataset_dir data/raw --out data/processed
```
This walks every video, extracts landmarks frame-by-frame with MediaPipe
Holistic, and writes `.npy` sequences + a `labels.csv` manifest + train/val/test
splits.
